### <a name="solution"></a>**Решение**  
В центре — **Rate Service**, выполняющий роль «мостика» между АБС и системами кол-центра:

1. **ABS Adapter**  
   - Запросы к АБС: события о изменении ставок приходят через шину от АБС, сбрасывает кеш при изменении
   - Кэширование в памяти (TTL 1 мин) для ускорения повторных запросов  

2. **File Exporter**  
   - CRON (00:05) → получить ставки через ABS Adapter → сформировать CSV/Excel → загрузить на SFTP  

3. **Internal Rates API**  
   - REST `/api/v1/rates/current` → читает из кэша/АБС → возвращает JSON → вызывается Internal Call Center System  

4. **Мониторинг и логирование**  
   - Проверка успешности SFTP-выгрузки (Prometheus Alert)  
   - Uptime и latency REST API (Grafana Dashboard)  
   - Централизованное логирование в ELK

#### Обоснование  
- АБС остаётся источником правды по ставкам
- Rate Service адаптирует формат и протокол для каждого кол-центра  
- Кэширование и асинхронная выгрузка минимизируют нагрузку на АБС

### <a name="alternatives"></a>**Альтернативы**  
1. **Партнёрский кол-центр читает напрямую из АБС**  
   - + нет промежуточного сервиса  
   - – внешние системы не могут обращаться в АБС, требования безопасности  
2. **REST API для партнёров**  
   - + актуальность в реальном времени  
   - – партнёры не готовы интегрироваться через API  
3. **Email-отправка файла**  
   - + быстрое внедрение  
   - – низкая надёжность, отсутствие автоматического контроля доставки  

---

### <a name="risks"></a>**Недостатки, ограничения и риски**  
- **Зависимость от SFTP**: сбои задержат передачу ставок партнёрам  
- **Сложность адаптера**: изменения в API АБС потребуют доработок Rate Service
